原型 · 详情页重设计

一个页面拆成两个，按钮全部浮起来

核心变化有两处：按钮从贴边平铺改成悬浮毛玻璃胶囊（更大、更明显、不和内容糊在一起）； 分享点开的人走独立的「接收页」，不再是同一个详情页套个参数 —— 他需要的信息和创建者完全不同。

1

底部只有一个悬浮胶囊，里面按身份放不同的按钮组合。创建者的「催一下 / 加人」下沉到参与者区块的标题行 —— 底部留给真正的动作（分享、编辑、撤回），三个按钮等宽，一眼看清。

为什么必须是两个页面，而不是一个页面加参数

一个页面加 ?from=share 的话，两件事会互相污染：
1. 布局没法两全 —— 详情页是信息密集型（信息卡 + 描述 + 参与者 + 时间线）， 接收页是留白型（四件事、大标题）。同一个文件里做两套布局，条件判断会把 WXML 撑成一团。

2. 权限和状态分支会翻倍 —— 详情页要处理「我是创建者 / 我是参与者 / 我是路人」三种， 接收页只处理「待我接受 / 我接过了 / 我是路人」。分开后每个页面的分支只有一半。

顺带解决了另一个问题：分享出去的卡片以前落在详情页，路人能看到完整的参与者列表和时间线， 其实没必要给他看这些。现在他只能看到该看的。

悬浮毛玻璃的几处取舍

项取值为什么
胶囊容器 左右 28rpx、底部 28rpx、圆角 44rpx、内边距 14rpx 留出边缘呼吸，不像贴边条那样"压住"内容
毛玻璃 background rgba(255,255,255,.78)
backdrop-filter blur(28rpx) saturate(180%)		 透出下面的内容但保证文字对比度；saturate 让透出来的橙色不发灰
不支持时的降级 rgba(255,255,255,.78) 已经接近不透明 Android 部分机型不认 backdrop-filter，靠底色兜住可读性
按钮高度 92rpx（普通 .btn 是 68rpx） 「要明显一点」—— 高度和字号一起加，比只加粗有效
配色 分享=品牌浅底 · 编辑=紫 · 撤回=红 · 拒绝=灰
接受=品牌实心 · 完成=薄荷 · 催办=琥珀		 每个动作一个色。原来一律白底，在毛玻璃上会和背景糊成一片，看着像"按钮没显示"
图标 16px（32rpx）线性图标，currentColor 跟随文字色 彩色底上只放文字辨识慢，带图标一眼认得出
撤回 浅红底 + 红字，不是实心红 破坏性操作要能看见但别太抓眼，避免误触

两个实现上的坑

1. 分享按钮必须是 button：小程序里 <view bindtap> 调不起微信转发面板， 只有 <button open-type="share"> 可以。所以要把它重置成和旁边按钮一模一样的外观 （::after { border: none } + 清 padding/margin）。

2. 接收页可能在冷启动时直接进入：从聊天卡片点进来不经过登录页， 所以接收页的 onLoad 必须自己 await getApp().ensureLogin()，否则拿不到 token 会白屏。
