## 0. 使用说明（先看这 5 行）

1. **优先级**：本仓库现有代码 > 本文件 > 官方文档。官方文档有些写法已过时（见 §4）。
2. 动手前必读三个文件：`sa-admin/.../module/business/category/`（完整 CRUD 范式）、`sa-base/.../common/domain/ResponseDTO.java`、`sa-admin/.../interceptor/AdminInterceptor.java`。
3. 新增业务优先复制 `category` 模块的目录结构，不要自创分层。
4. 改 `sa-base` 要谨慎：它被 `sa-admin` 和 `sa-app` 同时依赖，改动会影响两个应用。
5. 每次提交前过一遍 §16 自检清单。

## 1. 项目全景

### 1.1 三个模块

| 模块 | 职责 | 启动类 | 端口 | 依赖 |
|---|---|---|---|---|
| `sa-base` | 公共底座：工具、配置、拦截器基座、23 个 support 能力、系统级 domain | 无（jar） | — | 无 |
| `sa-admin` | 后台管理端：员工/角色/菜单/部门 + 业务示例（类目、商品、OA） | `AdminApplication` | 1024 | sa-base |
| `sa-app` | 微信小程序 C 端：会员登录、订阅消息（支付待做） | `AppApplication` | 1025 | sa-base |

**关键**：`sa-app` **不依赖** `sa-admin`。两个应用共享 `sa-base`，各自独立部署、独立启动类、独立端口、独立 token 体系。

### 1.2 技术栈

| 组件 | 版本 | 备注 |
|---|---|---|
| Java | 17 | 用 `var` 可以，但项目风格基本显式声明类型 |
| Spring Boot | 3.5.4 | jakarta 命名空间，**不要用 javax** |
| Sa-Token | 1.44.0 | 两套账号体系，见 §9 |
| MyBatis-Plus | 3.5.12 | 只做单表 CRUD，复杂 SQL 写 XML |
| Redis / Redisson | — | 缓存、分布式锁、Sa-Token 存储 |
| MySQL | 8.x | 库名 `smart_admin_v3` |
| Knife4j / OpenAPI3 | — | 注解用 `io.swagger.v3.oas.annotations.*` |
| Hutool / Guava / commons-lang3 | — | 工具类优先用这三个，别再引新库 |

## 2. 目录结构与分层

### 2.1 顶层目录（sa-admin / sa-app 同构）

```
src/main/java/net/lab1024/sa/{admin|app}
├── Application.java        启动类
├── config/                 Web、Sa-Token、第三方等配置
├── constant/               全局常量、缓存 key、Swagger tag
├── interceptor/            登录/权限拦截器
├── util/                   本应用专用工具（如 AdminRequestUtil、AppRequestUtil）
└── module/                 业务模块（一个业务一个一级包）
    ├── system/             系统功能（员工、角色、菜单、部门、登录）
    └── business/           业务功能（类目、商品、OA）
```

`sa-base` 顶层是 `common/`、`config/`、`constant/`、`handler/`、`listener/`、`module/`：
- `common/`：annoation、code、constant、domain、enumeration、exception、json、swagger、util、validator
- `handler/`：全局异常、MyBatis 填充
- `module/support/`：20+ 个通用能力，见 §14

### 2.2 模块内标准结构（务必照抄）

```
module/business/goods
├── constant/           GoodsStatusEnum.java        模块内枚举/常量
├── controller/         GoodsController.java        只做路由
├── service/            GoodsService.java           业务编排 + 校验
│                       GoodsQueryService.java      查询类业务可拆分
├── manager/            GoodsManager.java           事务 + 多 DAO 组合 + 缓存
├── dao/                GoodsDao.java               继承 BaseMapper
└── domain/
    ├── entity/         GoodsEntity.java            与表一一对应
    ├── form/           GoodsAddForm.java           请求对象
    │                   GoodsUpdateForm.java
    │                   GoodsQueryForm.java         继承 PageParam
    ├── vo/             GoodsVO.java                返回对象
    └── dto/            GoodsBaseDTO.java           内部传输（可选）
```

XML 固定放：`sa-admin/src/main/resources/mapper/{business|system}/{模块}/XxxMapper.xml`
扫描路径：`classpath*:/mapper/**/*.xml`（`DataSourceConfig` 里配置，无需额外声明）。

### 2.3 四层职责（官方定义，项目严格遵守）

| 层 | 只做 | 绝对不做 |
|---|---|---|
| **controller** | 接收请求、`@Valid` 简单校验、取当前用户、调用 service、返回 `ResponseDTO` | 业务逻辑、数据拼装、复杂参数校验、直接调 dao |
| **service** | 业务编排、业务校验（重名/状态/权限）、entity↔vo 转换、返回 `ResponseDTO` | 写复杂 SQL、开长事务、调第三方 |
| **manager** | `@Transactional` 事务、多 DAO 组合、缓存读写、第三方封装 | 返回 `ResponseDTO`、处理前端参数 |
| **dao** | 继承 `BaseMapper` + 自定义 XML 方法 | 业务判断、拼装 VO、写死常量 |

**层间调用只能自上而下**：controller → service → manager → dao。禁止 dao 调 service。

## 3. 硬性规范速查

### 3.1 必须（MUST）

| # | 规则 |
|---|---|
| 1 | URL 只写在**方法**上，类上不加 `@RequestMapping` |
| 2 | 不用 RESTful 语义，只用 `GET` / `POST`；URL = `/业务/子模块/动作` |
| 3 | 每个接口方法必须有 `@Operation(summary = "描述 @author 你的名字")` |
| 4 | Controller 方法参数不超过 5 个，超出封装 Form |
| 5 | 实体时间字段统一 `java.time.LocalDateTime` / `LocalDate` |
| 6 | 布尔字段/表字段用 `flag` 结尾：`deletedFlag` / `deleted_flag`，不用 `isDeleted` |
| 7 | 表名 `t_` 前缀，字段小写下划线；必备 `[module]_id`、`create_time`、`update_time` |
| 8 | 枚举型表字段注释必须列出全部取值：`COMMENT '状态 0待支付 1已支付 2已关闭'` |
| 9 | JavaBean 每个字段写多行注释；基本类型一律用包装类；不给默认值 |
| 10 | 新增实体/字段同步更新：Entity 注释、Form 校验、VO 暴露、XML 列名 |
| 11 | 后台接口加 `@SaCheckPermission("模块:动作")`，不需要登录的加 `@NoNeedLogin` |
| 12 | 事务方法 `@Transactional(rollbackFor = Exception.class)`，且只包 DB 操作 |
| 13 | 当前登录用户只在 controller 取（ThreadLocal），作为参数传给 service |
| 14 | 金额用 `bigint` 存**分**，禁止 `double`/`float`；日期时间用 `datetime` |

### 3.2 禁止（MUST NOT）

| # | 禁令 | 原因 |
|---|---|---|
| 1 | **禁止使用 MyBatis-Plus 的 `QueryWrapper` / `LambdaQueryWrapper`** | SQL 无法复用、慢查询无法定位。本项目 `sa-admin` 中 0 处使用，全部写 XML |
| 2 | XML 里禁止写死常量，必须由 dao 参数传入 | 改值要重新发版，且无法复用 |
| 3 | XML join 禁止用表别名，用表全名 | 多表关联时别名难以维护 |
| 4 | `Form` / `VO` 禁止继承 `Entity` | 表结构变化会污染接口契约 |
| 5 | `BO` / `Entity` 禁止出现在 controller 层 | 内部对象不应泄露到接口 |
| 6 | Controller 禁止写业务判断、禁止 try-catch 吞异常 | 污染路由层、掩盖问题 |
| 7 | Service 禁止直接返回 Entity | 会暴露表结构（如密码字段） |
| 8 | 禁止在循环里查库（N+1） | 改用 `IN` 批量查询 |
| 9 | 禁止打印手机号、密码、openid 全量、session_key | 敏感信息 |
| 10 | 禁止 `new` 一个 Spring Bean 或手动 `getBean` | 破坏 AOP（事务/缓存会失效） |

### 3.3 建议（SHOULD）

- 一个 Service 方法控制在 50 行内，超了就拆 `XxxQueryService` / `XxxValidatorService`。
- 类注释用项目模板（作者/日期/微信/邮箱/版权），新代码写自己的名字即可。
- `@Resource` 字段注入（项目统一风格，不用构造器注入）。
- 集合判空用 `CollectionUtils.isEmpty`，字符串用 `StringUtils.isBlank` / `StrUtil`。

## 4. 官方规范 vs 本项目实际（最容易踩的坑）

官方文档是 Swagger2 时代写的，照抄会**编译不过**或**风格不一致**。以本表为准：

| 场景 | 官方文档写法 | 本项目实际写法 |
|---|---|---|
| 接口注释 | `@ApiOperation("xxx @author 卓大")` | `@Operation(summary = "xxx @author 卓大")`（OpenAPI3） |
| 类级文档分组 | `@Api(tags = "...")` | `@Tag(name = XxxSwaggerTagConst.Xxx.YYY)` |
| 成功返回 | `ResponseDTO.succ()` / `ResponseDTO.wrap(x)` | **`ResponseDTO.ok()` / `ResponseDTO.ok(data)`** |
| 失败返回 | `ResponseCodeConst.XXX` | `ResponseDTO.error(UserErrorCode.XXX)` / `ResponseDTO.userErrorParam("提示")` |
| 参数校验 | `javax.validation.*` | **`jakarta.validation.*`** |
| 数据库条件查询 | 未提 | 官方口头"禁用 Wrapper"，项目实践：**一律写 XML** |
| 事务 rollbackFor | 文档自相矛盾（`Exception` / `Throwable`） | 统一 `Exception.class` |
| 时间字段赋值 | — | 有 `MybatisPlusFillHandler`：字段名叫 `createTime`/`updateTime` 且为 null 时自动填充；手动赋值优先 |
| 逻辑删除 | — | **没有全局 `@TableLogic`**，查询/删除都要显式带 `deletedFlag` 条件 |
| 分页 | — | `XxxQueryForm extends PageParam`，dao 传 `Page`，返回 `PageResult<T>` |

## 5. URL 与接口约定

### 5.1 命名

```
GET  /goods/get/{goodsId}          查详情
POST /goods/query                  列表/分页查询
POST /goods/add                    新增
POST /goods/update                 更新
GET  /goods/delete/{goodsId}       删除
GET  /goods/update/status/{id}     状态变更
```

规则：`/名词/名词/动词`，动作放最后；**不使用** `/goods` PUT/DELETE 这种 RESTful 风格。

### 5.2 权限

```java
@Operation(summary = "添加商品 @author 张三")
@PostMapping("/goods/add")
@SaCheckPermission("goods:add")
public ResponseDTO<String> add(@RequestBody @Valid GoodsAddForm form) { ... }
```

- 权限码格式：`模块:动作`，与菜单表 `t_menu.api_perms` 对应，后台「角色-菜单」里勾选后才会出现在用户的 `permissionList`。
- 超管（`administratorFlag=true`）在拦截器里**直接跳过权限校验**。
- 免登录接口（登录、验证码、支付回调）加 `@NoNeedLogin`，同时它会自动从 `UrlConfig.authUrl` 的鉴权清单里排除。
- 特殊放行用 `@SaIgnore`（比 `@NoNeedLogin` 更彻底，连用户注入都跳过）。

### 5.3 小程序端

- 所有接口前缀 `/api`，由 `AppInterceptor` 统一校验 `App-Token`，**不做 RBAC**。
- 只有 `/api/auth/login` 标 `@NoNeedLogin`。
- 新增接口若忘加 `/api` 前缀，会被 `AdminInterceptor` 拦截并返回 30007。

## 6. 统一返回与错误码

```java
@Data
public class ResponseDTO<T> {
    private Integer code;      // 0=成功；非 0 见错误码
    private String level;      // system / user
    private String msg;
    private Boolean ok;
    private T data;
    private Integer dataType;
}
```

常用静态方法：

```java
ResponseDTO.ok()                     // 成功无数据
ResponseDTO.ok(data)                 // 成功带数据
ResponseDTO.userErrorParam("手机号格式错误")   // 参数类错误，level=user
ResponseDTO.error(UserErrorCode.DATA_NOT_EXIST)  // 标准错误码
ResponseDTO.error(UserErrorCode.NO_PERMISSION, "自定义提示")
```

错误码位置：

| 类 | 用途 | 关键值 |
|---|---|---|
| `UserErrorCode` | 用户可感知的错误 | `30002 DATA_NOT_EXIST`、`30005 NO_PERMISSION`、`30007 LOGIN_STATE_INVALID`、`30011 LOGIN_FAIL_WILL_LOCK`、`30012 LOGIN_ACTIVE_TIMEOUT` |
| `SystemErrorCode` | 系统级错误 | `10001 SYSTEM_ERROR` 等 |

新增错误码：在对应枚举里追加，`code` 段位不要与现有冲突（用户级 3xxxx，系统级 1xxxx）。

## 7. 参数校验

```java
@Data
public class GoodsAddForm {

    @Schema(description = "商品名称", required = true)
    @NotBlank(message = "商品名称不能为空")
    @Length(max = 50, message = "商品名称最多50字符")
    private String goodsName;

    @Schema(description = "商品状态")
    @SchemaEnum(desc = "商品状态", value = GoodsStatusEnum.class)   // 给前端生成枚举下拉
    @CheckEnum(value = GoodsStatusEnum.class, required = true, message = "商品状态错误")  // 后端校验取值
    private Integer status;

    @Schema(description = "价格（分）")
    @NotNull(message = "价格不能为空")
    @Min(value = 0, message = "价格不能为负")
    private Long price;
}
```

- 枚举不要传字符串，传 `Integer` value，用 `@CheckEnum` 校验。
- 分页表单继承 `PageParam`（自带 `pageNum/pageSize`，上限 500）。
- Controller 只写 `@Valid`，业务校验放 service。

## 8. 异常与事务

### 8.1 异常

- 业务异常抛 `BusinessException("提示")`，`GlobalExceptionHandler` 统一转 `ResponseDTO`。
- **不要**在 service 里 `try-catch` 后返回 `ResponseDTO.error()` 又吞掉堆栈；需要记录时 `log.error(msg, e)`。
- Controller 不写 try-catch。

### 8.2 事务

```java
// ✅ 正确：service 只做校验，manager 管事务
public ResponseDTO<String> upOrDown(Long id, Long swapId) {
    // 一堆校验（不占连接）
    goodsManager.upOrDown(entity, swapEntity);
    return ResponseDTO.ok();
}

// GoodsManager
@Transactional(rollbackFor = Exception.class)
public void upOrDown(GoodsEntity a, GoodsEntity b) { ... }
```

三个坑：
1. `@Transactional` 方法内部 `this.otherMethod()` **事务不生效**（未走代理）→ 拆到别的类，或用 `AopContext.currentProxy()`（启动类已开 `exposeProxy = true`）。
2. 事务方法里不要做 HTTP 调用、发消息，会长时间占用连接。
3. 只读查询不要加事务。

## 9. 登录与权限（两套体系，别混）

| 维度 | sa-admin | sa-app |
|---|---|---|
| Sa-Token 实例 | `StpUtil`（loginType=`login`） | `StpLogic("app")`（Bean 名 `stpAppLogic`） |
| 请求头 | `Authorization: Bearer <token>` | `App-Token: Bearer <token>` |
| Redis key | `satoken:login:*` | `satoken:app:*` |
| 拦截器 | `AdminInterceptor`，`/**`（排除 Swagger） | `AppInterceptor`，仅 `/api/**` |
| 用户来源 | `t_employee`，`loginId = "1:{employeeId}"` | `t_wx_member`，`loginId = "{memberId}"` |
| 权限 | `@SaCheckPermission` + 菜单 perms | 无 RBAC，只校验登录 |
| 活跃超时 | 由三级等保配置决定（可能冻结） | `activeTimeout = -1`，永不冻结 |
| 并发登录 | 单端（`isConcurrent=false`），后登踢前登 | 同左 |

**因为 token 的 Redis key 前缀不同，会员 token 塞进 `Authorization` 也访问不了后台接口**——这是两套体系的关键隔离点，改动时不要破坏。

### 9.1 取当前用户

```java
// sa-admin：只在 controller 取
RequestEmployee requestUser = AdminRequestUtil.getRequestUser();
return goodsService.add(form, requestUser);

// sa-app：任意 /api/** 位置都可取（拦截器已放入上下文）
Long memberId = AppRequestUtil.getMemberId();
String openId = AppRequestUtil.getOpenId();
```

底层都是 `SmartRequestUtil` 的 ThreadLocal，`afterCompletion` 里已清理，**不会内存泄漏**，但**不要跨线程使用**（异步任务里会是 null）。

### 9.2 新增后台接口的三步

1. Controller 方法加 `@SaCheckPermission("模块:动作")`。
2. 后台「系统管理 → 菜单管理」新增菜单/按钮，`api_perms` 填同样的权限码。
3. 「角色管理」给角色勾上该菜单，用户重新登录生效（权限有缓存，见 §11）。

## 10. 数据访问

### 10.1 Entity

```java
@Data
@TableName("t_goods")
public class GoodsEntity implements Serializable {

    private static final long serialVersionUID = 1L;

    @TableId(type = IdType.AUTO)
    private Long goodsId;

    /**
     * 商品名称
     */
    private String goodsName;

    /**
     * 是否删除
     */
    private Boolean deletedFlag;

    /**
     * 创建时间
     */
    private LocalDateTime createTime;

    /**
     * 更新时间
     */
    private LocalDateTime updateTime;
}
```

- 字段与表**严格一一对应**，不多不少。
- 主键用 `IdType.AUTO`，配合表自增。
- 不要用 `@TableField(exist=false)` 塞非表字段，改用 VO。

### 10.2 Dao + XML

```java
@Mapper
public interface GoodsDao extends BaseMapper<GoodsEntity> {

    /**
     * 按名称模糊查询
     *
     * @param keyword     关键词
     * @param deletedFlag 删除标识
     * @return 列表
     */
    List<GoodsEntity> queryByName(@Param("keyword") String keyword,
                                  @Param("deletedFlag") Boolean deletedFlag);

    /**
     * 分页查询
     */
    List<GoodsVO> queryPage(@Param("query") GoodsQueryForm query, Page<?> page);
}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="net.lab1024.sa.admin.module.business.goods.dao.GoodsDao">

    <select id="queryByName" resultType="net.lab1024.sa.admin.module.business.goods.domain.entity.GoodsEntity">
        SELECT * FROM t_goods
        WHERE deleted_flag = #{deletedFlag}
        <if test="keyword != null and keyword != ''">
            AND goods_name LIKE CONCAT('%', #{keyword}, '%')
        </if>
        ORDER BY goods_id DESC
    </select>

    <select id="queryPage" resultType="net.lab1024.sa.admin.module.business.goods.domain.vo.GoodsVO">
        SELECT t_goods.*, t_category.category_name
        FROM t_goods
        LEFT JOIN t_category ON t_goods.category_id = t_category.category_id
        WHERE t_goods.deleted_flag = #{query.deletedFlag}
    </select>
</mapper>
```

规约：
- `namespace` 写 dao 全类名，`id` 与 dao 方法名一致。
- 常量一律 `#{}` 传参，不写死。
- join 用**表全名**。
- 分页：dao 参数带 `Page<?>`，MyBatis-Plus 分页插件自动改写 SQL 并回填 total。
- 列表接口必须带 `deleted_flag` 条件。

### 10.3 逻辑删除

项目**没有**全局 `@TableLogic`，所有查询/更新/删除都要显式处理：

```java
// 删除 = 更新标记
GoodsEntity entity = new GoodsEntity();
entity.setGoodsId(id);
entity.setDeletedFlag(true);
goodsDao.updateById(entity);
```

## 11. 缓存

### 11.1 三种方式

```java
// 1) 注解式（推荐，key = cache:name:key）
@Cacheable(value = "goods_detail#30m", key = "#goodsId", unless = "#result == null")
public GoodsVO getDetail(Long goodsId) { ... }

@CachePut(value = "goods_detail#30m", key = "#entity.goodsId")
public GoodsVO refresh(GoodsEntity entity) { ... }

@CacheEvict(value = "goods_detail#30m", key = "#goodsId")
public void clear(Long goodsId) { }

// 2) 直接读写 Redis（计数、锁、验证码、任意对象）
redisService.get(key);
redisService.set(key, value, seconds);
redisService.delete(key);

// 3) 缓存管理（清理、列举，不能读写值）
cacheService.cacheNames();
cacheService.cacheKey(cacheName);
cacheService.removeCache(cacheName);
```

### 11.2 TTL 语法（`CustomRedisCacheManager`）

`cacheName#ttl`，支持 `10s` / `30m` / `2h` / `7d`，`#-1` 表示永不过期，**不写默认 7 天**。

```
"goods_detail#30m"  →  Redis key: cache:goods_detail:123，30 分钟过期
```

### 11.3 key 命名

- 常量集中在 `AdminCacheConst` / `AppCacheConst`，格式 `模块_业务`，如 `login_request_employee`。
- 不要用类全名或随机字符串。

### 11.4 必须清缓存的时机

| 动作 | 要清 |
|---|---|
| 改员工信息 / 角色 / 菜单 | `login_request_employee`、`login_user_permission` |
| 登出 | 同上（`LoginService.clearLoginEmployeeCache`） |
| 改字典、配置 | 对应 `xxx_cache` |
| 小程序改会员资料 / 手机号 | `app_member_login` |

> 缓存不清理是这套项目最常见的数据不一致来源。

## 12. 配置规范

### 12.1 放哪里

| 配置类型 | 位置 |
|---|---|
| 数据库、Redis、Sa-Token、邮件、job 等通用项 | `sa-base/src/main/resources/{env}/sa-base.yaml` |
| 应用独有（端口、项目名、模块开关） | `sa-{module}/src/main/resources/{env}/application.yaml` |
| 敏感值（密码、appsecret、私钥） | 环境变量 + `${ENV_NAME:}` 占位 |

### 12.2 新增配置项

```yaml
# 1) yaml
wx:
  miniapp:
    appid: ${WX_MINIAPP_APPID:}
    timeout: 5000

# 2) 绑定类
@Data
@Component
@ConfigurationProperties(prefix = "wx.miniapp")
public class WxProperties {
    private String appid;
    private int timeout = 5000;
}
```

**不要**在代码里 `@Value` 散落取值（项目除 `RestClientConfig` 外基本用 `@ConfigurationProperties`）。

### 12.3 环境

四个 profile：`dev`（默认）/ `test` / `pre` / `prod`。新增配置**四个环境都要加**，否则打包后某环境启动失败（yaml 缺失占位符会抛 `Could not resolve placeholder`）。

## 13. 日志与审计

```java
@Slf4j
@Service
public class GoodsService {
    public void doSomething(Long id) {
        log.info("商品上下架, id={}", id);            // 用占位符，不要字符串拼接
        log.warn("商品状态异常, id={}, status={}", id, status);

    }
}
```

禁止：打印密码、`session_key`、完整 openid/手机号（需要时脱敏）。

## 15. 新增一个业务模块的标准流程

以「优惠券 coupon」为例：

### Step 1 · 建表

```sql
CREATE TABLE `t_coupon` (
  `coupon_id`     BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '优惠券ID',
  `coupon_name`   VARCHAR(64)  NOT NULL COMMENT '名称',
  `status`        TINYINT      NOT NULL DEFAULT 0 COMMENT '状态 0未开始 1进行中 2已结束',
  `deleted_flag`  TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否删除',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`coupon_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='优惠券';
```

### Step 2 · 建目录

```
sa-admin/src/main/java/net/lab1024/sa/admin/module/business/coupon/
├── constant/CouponStatusEnum.java
├── controller/CouponController.java
├── service/CouponService.java
├── dao/CouponDao.java
└── domain/{entity,form,vo}/
sa-admin/src/main/resources/mapper/business/coupon/CouponMapper.xml
```

### Step 3 · Entity

```java
@Data
@TableName("t_coupon")
public class CouponEntity implements Serializable {

    private static final long serialVersionUID = 1L;

    @TableId(type = IdType.AUTO)
    private Long couponId;

    /**
     * 优惠券名称
     */
    private String couponName;

    /**
     * 状态
     *
     * @see CouponStatusEnum
     */
    private Integer status;

    /**
     * 是否删除
     */
    private Boolean deletedFlag;

    private LocalDateTime createTime;

    private LocalDateTime updateTime;
}
```

### Step 4 · 枚举

```java
@Getter
@AllArgsConstructor
public enum CouponStatusEnum implements BaseEnum {
    NOT_START(0, "未开始"),
    RUNNING(1, "进行中"),
    FINISHED(2, "已结束");

    private final Integer value;
    private final String desc;
}
```

### Step 5 · Dao

```java
@Mapper
public interface CouponDao extends BaseMapper<CouponEntity> {
    List<CouponVO> queryPage(@Param("query") CouponQueryForm query, Page<?> page);
}
```

### Step 6 · Service

```java
@Service
public class CouponService {

    @Resource
    private CouponDao couponDao;

    public ResponseDTO<PageResult<CouponVO>> query(CouponQueryForm queryForm) {
        Page<?> page = SmartPageUtil.convert2PageQuery(queryForm);
        List<CouponVO> list = couponDao.queryPage(queryForm, page);
        return ResponseDTO.ok(SmartPageUtil.convert2PageResult(page, list));
    }

    public ResponseDTO<String> add(CouponAddForm addForm) {
        // 业务校验
        CouponEntity entity = SmartBeanUtil.copy(addForm, CouponEntity.class);
        entity.setDeletedFlag(false);
        couponDao.insert(entity);
        return ResponseDTO.ok();
    }
}
```

### Step 7 · Controller

```java
@RestController
@Tag(name = "优惠券")
public class CouponController {

    @Resource
    private CouponService couponService;

    @Operation(summary = "分页查询优惠券 @author 你的名字")
    @PostMapping("/coupon/query")
    @SaCheckPermission("coupon:query")
    public ResponseDTO<PageResult<CouponVO>> query(@RequestBody @Valid CouponQueryForm queryForm) {
        return couponService.query(queryForm);
    }

    @Operation(summary = "添加优惠券 @author 你的名字")
    @PostMapping("/coupon/add")
    @SaCheckPermission("coupon:add")
    public ResponseDTO<String> add(@RequestBody @Valid CouponAddForm addForm) {
        return couponService.add(addForm);
    }
}
```

### Step 8 · 配权限

在「菜单管理」新增菜单/按钮，`api_perms` 填 `coupon:query`、`coupon:add`，再到「角色管理」授权。

### Step 9 · 自测

启动 → Swagger `http://localhost:1024/doc.html` → 登录拿 token → 调接口。

## 16. 提交前自检清单

- [ ] URL 在方法上，没有类级 `@RequestMapping`
- [ ] 每个接口有 `@Operation(summary = "... @author xxx")`
- [ ] 后台接口有 `@SaCheckPermission`，免登录接口有 `@NoNeedLogin`
- [ ] Controller 没有业务逻辑，参数用 `@Valid`
- [ ] Service 返回 `ResponseDTO`，没有返回 Entity
- [ ] 事务在 manager 层，`rollbackFor = Exception.class`
- [ ] **没有使用 `QueryWrapper` / `LambdaQueryWrapper`**

- [ ] 查询都带 `deleted_flag` 条件
- [ ] Entity 字段与表一一对应，注释齐全
- [ ] Boolean 字段以 `Flag` 结尾
- [ ] 表单有 `@Schema` + `jakarta.validation` 校验
- [ ] 新增了表/字段：建表 SQL、Entity、Form、VO、XML、注释 全部同步
- [ ] 新增配置项：四个环境的 yaml 都加了

- [ ] 没有打印敏感信息
- [ ] `mvn -pl 模块 -am compile` 通过

## 17. 已知坑（都是实际踩过的）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 启动报 `Port 64660 already in use` | 宿主注入 `SERVER__PORT` 环境变量，覆盖 yaml | 启动加 `--server.port=1024` |
| 2 | 新增模块启动报缺 `DataScopePlugin` | `sa-base` 的 `DataSourceConfig` 强依赖该 Bean，实现只在 `sa-admin` | 新模块补一个空实现（参考 `sa-app/config/AppDataScopePlugin`） |
| 3 | 新增枚举后 admin 编译不过 | 本地仓库的 `sa-base` jar 是旧的 | 先 `mvn -pl sa-base install -DskipTests` |
| 4 | `@Transactional` 不生效 | 类内自调用，未走代理 | 拆 manager 或用 `AopContext.currentProxy()` |
| 5 | 改角色后权限没变 | `login_user_permission` 有 7 天缓存 | 调 `clearUserPermission` 或重新登录 |
| 6 | 用户改不动数据但没报错 | 超管跳过权限、普通用户权限码没配 | 检查菜单 `api_perms` 与注解是否一致 |
| 7 | 时间字段为 null | 实体字段名不是 `createTime`/`updateTime`，或表无默认值 | 手动赋值或按规范命名 |
| 8 | 分页 total 为 0 | dao 没接收 `Page` 参数，或 SQL 里写了 `LIMIT` | 去掉手写 LIMIT，加 `Page` 参数 |
| 9 | 小程序接口 404 / 30007 | 路径没加 `/api`，被后台拦截器拦了 | 统一 `/api/**` |
| 10 | 会员 token 能访问后台接口 | 破坏了 token 隔离（把会员登录改成 `StpUtil`） | 必须用 `stpAppLogic` |

### 技术债（已知，改动时注意）

- `sa-app` 的 `WxMemberService` / `WxSubscribeService` 使用了 `LambdaQueryWrapper`，**违反本项目"禁用 Wrapper"规范**（当时为快速联调）。二次开发该模块时建议改成 XML，与 `sa-admin` 对齐。
- `sa-app` 的 `AppDataScopePlugin` 是空实现（C 端无数据权限），不要误以为它有隔离能力。
- `LoginService.getEmployeeIdByLoginId()` 用 `substring(2)` 解析 loginId，未校验前缀。目前因两套 token 体系隔离而无风险，但若将来共享 `StpLogic`，必须补 `1:`/`S:` 前缀白名单，否则会员可能越权拿到员工身份。
