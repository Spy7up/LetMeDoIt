# 「让我做」小程序接口说明（sa-app）

> 模块：`sa-app` · 前缀 `/api` · 鉴权 `App-Token` · 时间格式 `yyyy-MM-dd HH:mm:ss`
> 建表脚本：`docs/sql/letmedoit_task.sql`
> 产品规则来源：`letmedoit-miniprogram/docs/让我做-v1.1-产品与技术方案.md`

---

## 1. 通用约定

| 项 | 说明 |
|---|---|
| 前缀 | 全部 `/api/**`，由 `AppInterceptor` 统一校验登录 |
| 请求头 | `App-Token: Bearer <token>`（与后台 `Authorization` 物理隔离） |
| 时间入参 | `yyyy-MM-dd HH:mm:ss`（带 `@JsonFormat`，不要传 ISO / 时间戳） |
| 时间出参 | 同格式，全局 Jackson 配置 |
| 返回结构 | `{ code, level, msg, ok, data, dataType }`，`code = 0` 成功 |
| 分页入参 | `pageNum`、`pageSize`（上限 500） |
| 当前用户 | 服务端从 token 取，**不接受前端传 memberId 做身份** |

**唯一需要免登录的接口**：`/api/auth/login`（已有）。任务、好友、通知全部要登录。

## 2. 接口清单

### 2.1 任务

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/task/query` | `TaskQueryForm` | `PageResult<TaskListVO>` |
| GET | `/api/task/get/{taskId}` | — | `TaskDetailVO` |
| GET | `/api/task/summary` | — | `TaskSummaryVO` |
| GET | `/api/task/stats` | — | `TaskStatsVO` |
| POST | `/api/task/add` | `TaskAddForm` | `TaskDetailVO` |
| POST | `/api/task/update` | `TaskUpdateForm` | `TaskDetailVO` |
| POST | `/api/task/accept` | `{ taskId }` | `TaskDetailVO` |
| POST | `/api/task/reject` | `{ taskId, reason }` | `TaskDetailVO` |
| POST | `/api/task/complete` | `{ taskId, remark, images[] }` | `TaskDetailVO` |
| POST | `/api/task/cancel` | `{ taskId }` | `TaskDetailVO` |
| POST | `/api/task/remind` | `{ taskId }` | `TaskDetailVO` |
| POST | `/api/task/participant/add` | `{ taskId, memberIds[] }` | `TaskDetailVO` |

列表查询体：

```json
{
  "role": 1,
  "status": 2,
  "overdueFlag": false,
  "keyword": "",
  "pageNum": 1,
  "pageSize": 10
}
```

- `role`：`1` 我收到的（我是参与者）／`2` 我发出的（我是委托人），必填
- `status`：`0` 预约中 `1` 待接受 `2` 进行中 `3` 已完成 `4` 已拒绝 `5` 已撤回，不传为全部
- `overdueFlag`：只看逾期（**派生状态**，不是 `status` 的取值，等价于 `status IN (1,2) AND deadline < now`）
- 前端五个筛选的映射：全部 → 不传 status；待接受 → `1`；进行中 → `2`；已完成 → `3`；已逾期 → `overdueFlag: true`

布置任务体：

```json
{
  "title": "晾衣服",
  "description": "阳台的衣服，白的别和深色混",
  "memberIds": [2, 3],
  "completionMode": 2,
  "deadline": "2026-10-21 23:10",
  "startTime": null,
  "remindMinutes": 10
}
```

- `completionMode`：`1` 任一人完成（其余自动跳过）／`2` 全员完成
- `memberIds` 1~10 个，且必须都是好友（可以包含自己）
- `remindMinutes`：0 不提醒；非 0 时后端会算出 `remind_time` 供定时作业扫描

## 3. 关键业务规则（接口行为，前端需要知道）

1. **状态是两层的**。`t_task.status` 是聚合状态（由参与者状态 + 完成条件算出，写入时落库）；每个参与者还有自己的 `participant.status`（0 待接受 1 已接受 2 已完成 3 已拒绝 4 已跳过）。
2. **「任一人完成」会跳过其他人**。任一人 complete 后，其余 `0/1` 的人自动变 `4 已跳过`，不再提醒。
3. **权限位服务端算**。`TaskDetailVO` 里的 `canAccept / canReject / canComplete / canCancel / canRemind / canAddParticipant / canEdit` 直接决定按钮显隐，前端不要再自己推。其中 `canEdit`：预约中/待接受不限次数，进行中只给一次（`t_task.edit_count` 只在进行中累加，见 `docs/sql/letmedoit_task_edit_count.sql`）。
4. **拒绝只拒绝自己那一格**，任务本身继续给别人；全部拒绝时任务才变「已拒绝」。
5. **催办限频 60 秒**，超频返回 `code=30001` + 提示「刚催过啦」。
6. **预约任务到点自动生效**，由 `TaskScheduleJob`（每分钟）把「预约中」翻成「待接受」，并重排提醒时间。
7. **到期提醒**同样由该作业扫描 `remind_time`，只发给还没完成的人，发完清空 `remind_time` 防重复。
8. **并发安全**：所有状态流转都是 `UPDATE ... WHERE status = 旧值`，受影响行数为 0 时抛「任务状态已变化，请刷新后重试」。

## 4. 与小程序 mock 的路径对照（切换环境时改这里）

前端 `services/*.js` 目前按 mock 的路径写的，接真实后端需要改 URL 与入参形状：

| 前端方法 | mock 路径 | 后端路径 | 入参变化 |
|---|---|---|---|
| `task.list` | `GET /tasks?role=&status=` | `POST /api/task/query` | GET→POST，`role` 由 `'assignee'` 改成 `1`，`status` 由字符串改成数字 |
| `task.detail` | `GET /tasks/{id}` | `GET /api/task/get/{id}` | 路径变化 |
| `task.create` | `POST /tasks` | `POST /api/task/add` | `participantIds` → `memberIds`，`completionMode` `'any'/'all'` → `1/2`，时间格式改 `yyyy-MM-dd HH:mm:ss` |
| `task.accept` | `POST /tasks/{id}/accept` | `POST /api/task/accept` | id 放进 body |
| `task.reject` | `POST /tasks/{id}/reject` | `POST /api/task/reject` | id 放进 body |
| `task.complete` | `POST /tasks/{id}/complete` | `POST /api/task/complete` | id 放进 body |
| `task.cancel` | `POST /tasks/{id}/cancel` | `POST /api/task/cancel` | id 放进 body |
| `task.remind` | `POST /tasks/{id}/remind` | `POST /api/task/remind` | id 放进 body |
| `task.addParticipant` | `POST /tasks/{id}/participants` | `POST /api/task/participant/add` | 单个人 → `memberIds[]` |
| `task.summary` | `GET /tasks/summary` | `GET /api/task/summary` | 字段名一致 |
| `task.stats` | `GET /tasks/stats` | `GET /api/task/stats` | 一致 |

## 5. 部署与联调

### 5.1 建表

执行 `docs/sql/letmedoit_task.sql`（6 张新表 + `t_wx_member.invite_code` 字段）。

> **通知表叫 `t_task_notice`，不能叫 `t_notice`**：sa-admin 自带的 `t_notice` 是站内公告表（列完全不同）。
> 脚本里 `CREATE TABLE IF NOT EXISTS t_notice` 会被静默跳过，随后写通知时报
> `Unknown column 'member_id'`——这个坑已经踩过，改掉了。

建表后应有：`t_friend` / `t_friend_request` / `t_task` / `t_task_participant` / `t_task_event` / `t_task_notice`。

### 5.2 启动

```bash
# 编译（离线可用；本机 mvn 不在 PATH 时用 wrapper 里的）
mvn -o -pl sa-app -am package -DskipTests

# 启动
java -jar sa-app/target/sa-app-dev-3.0.0.jar --server.port=1025
```

- 数据库 / Redis 连接在 `sa-base/src/main/resources/dev/sa-base.yaml`
- Swagger：`http://localhost:1025/doc.html`，分组「小程序-任务 / 小程序-好友 / 小程序-服务通知」
- 微信登录两种模式（`sa-app/.../dev/application.yaml`）：

  | 模式 | 配置 | 登录行为 | 适用 |
  |---|---|---|---|
  | mock | `wx.miniapp.mock: true` | 用 `mock_md5(code)` 当 openid，不调微信接口，任意 code 都能登 | 本地无 AppID、`e2e.js` 自动化联调 |
  | 真实 | `wx.miniapp.mock: false` + `appid`/`secret` | `wx.login` 的 code 真调 `jscode2session`，假 code 必然失败 | 开发者工具 / 真机联调 |

  > dev 环境已切真实模式：`appid: wxaa5051e002ac4fba`（与 `letmedoit-miniprogram/project.config.json` 一致）。
  > **secret 目前写在 yaml 默认值里，上线前请改成环境变量 `WX_MINIAPP_SECRET`，不要提交进仓库。**

> 宿主环境若存在 `SERVER__PORT` 会覆盖 yaml，务必用 `--server.port=` 显式指定。

### 5.3 前后端联调

小程序侧 `config/index.js` 的 `ENV = 'dev'` → `http://192.168.31.79:8081`（局域网上的 sa-app），`services/*` 无需改动。

- **开发者工具**：需勾「不校验合法域名」；AppID 用 `project.config.json` 里的 `wxaa5051e002ac4fba`，与后端 appid 一致，`wx.login` 的 code 才能兑换
- **真机调试**：手机与服务器同网段，能直连 192.168.31.79:8081
- 切回本机后端：把 `ENV_CONFIG.dev.baseUrl` 改回 `http://127.0.0.1:1025`

真后端联调用 `letmedoit-miniprogram/tools/e2e.js`（只桩 `wx`，其余走真实请求层）：

```bash
cd letmedoit-miniprogram
node tools/e2e.js                     # 默认跟随 config 里的 dev 地址
node tools/e2e.js http://ip:1025      # 指定后端
```

> **脚本要求后端开 `wx.miniapp.mock: true`**：它用假 code 登录，真实模式下会直接提示并退出（exit=2）。
> 真实登录链路只能在微信开发者工具里人工验证。

覆盖：mock 登录 → 邀请码加好友 → 好友申请/同意 → 布置多人任务 → 列表/详情/权限位 →
接受/完成 → 催办限频 → 拒绝 → 撤回 → 任一人完成自动跳过 → 通知读写 → 摘要统计 →
筛选 → 错误路径 → 30007 静默重登。**mock 实例下 72 项全通过。**

脚本账号用固定 mock code（`e2e_granny_v1` / `e2e_kid_v1`），表姐账号每次运行新建，
避免「已经是好友了」。同一 IP 登录限频 30 次/分钟，脚本内已复用 token。

### 5.4 联调中修掉的三个坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 布置任务报「截止时间不能早于现在」，后端存的时间比选的早 8 小时 | 前端 `apiTime()` 把 `toISOString()` 的 `…Z` 串按本地时间解析（正则先匹配到 `13:00`，忽略时区） | `utils/format.js#parseTime` 先识别带时区标记的 ISO，交给 `new Date()` 解析；后端格式 `yyyy-MM-dd HH:mm:ss` 仍手工按本地构造 |
| 写通知报 `Unknown column 'member_id'` | `t_notice` 与框架自带表重名，建表被跳过 | 业务通知表改名 `t_task_notice`（DDL / `@TableName` / `NoticeMapper.xml` 同步） |
| 「我的」页邀请码空白 | `t_wx_member.invite_code` 有值，但 `WxMemberVO` / `RequestMember` 没有这个字段，`/api/member/info` 一直没返回 | VO 与 `RequestMember` 补 `inviteCode`；`currentMember()` 发现为空时回源一次并刷新登录态缓存；小程序 `adapt.member` 补字段，另用 `/api/friend/invite` 兜底 |

## 7. 数据模型速查

```
t_friend            好友关系（双写两行，uk_member_friend）
t_friend_request    好友申请（0 待处理 1 已同意 2 已拒绝）
t_task              任务 + 聚合状态（0 预约中 1 待接受 2 进行中 3 已完成 4 已拒绝 5 已撤回）
t_task_participant  参与者（一人一格，uk_task_member；0 待接受 1 已接受 2 已完成 3 已拒绝 4 已跳过）
t_task_event        任务事件（append-only，详情时间线 + 后台追溯）
t_task_notice       服务通知（fields_json 直接驱动卡片渲染）
```

索引按查询路径建的：`t_task(idx_creator_status, idx_status_deadline, idx_remind_time)`、`t_task_participant(idx_member_status, uk_task_member)`、`t_task_notice(idx_member_read)`。
