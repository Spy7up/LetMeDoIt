# 微信小程序一键登录改造方案（V2 · 定稿）

> 决策已确认：**外部 C 端会员 / 不与员工打通 / 会员不冻结 / 已有开放平台账号 / 需要支付与订阅消息**  
> 技术栈：Spring Boot 3.5.4 + Sa-Token 1.44.0 + Redis + MyBatis-Plus + Redisson

---

## 0. 架构结论（一句话）

**新增一套独立的会员账号体系（`t_wx_member`）+ 独立的 Sa-Token 账号体系（`StpMemberUtil`，独立 token-name）+ `wx.login` 换 openid 签发 token。**  
后台员工体系零改动，会员体系与员工体系在 token、缓存、权限、超时策略上完全隔离。

### 为什么不再共享 StpLogic

初版方案建议"共享 StpLogic + loginId 前缀"，在你确认「不打通员工 + 不冻结」后不再合适：

| 问题               | 共享 StpLogic                               | 独立 StpLogic（选定）                                    |
| ---------------- | ----------------------------------------- | -------------------------------------------------- |
| 会员 token 越权打后台接口 | 必须补 `1:`/`S:` 前缀校验，否则会员 token 可拿到员工甚至超管身份 | **物理隔离**：token 存在 `satoken:member:*`，`StpUtil` 读不到 |
| 会员不被冻结           | `activeTimeout` 是全局配置，改不了                 | 独立 `SaTokenConfig`，`activeTimeout = -1`            |
| header 冲突        | 共用 `Authorization`                        | 会员用 `Member-Token`，互不干扰                            |
| 后台代码改动           | 需改 `LoginService`、`AdminInterceptor`      | **零改动**                                            |

> 代价：小程序前端请求头要从 `Authorization` 改成 `Member-Token`。新前端，成本为零。

## 3. Sa-Token 多账号体系落地

### 3.1 配置 Bean

```java
// sa-base/src/main/java/net/lab1024/sa/base/config/MemberTokenConfig.java
@Configuration
public class MemberTokenConfig {

    public static final String LOGIN_TYPE = "member";
    public static final String TOKEN_NAME = "Member-Token";

    @Bean("stpMemberLogic")
    public StpLogic stpMemberLogic() {
        StpLogic logic = new StpLogic(LOGIN_TYPE);

        SaTokenConfig config = new SaTokenConfig();
        config.setTokenName(TOKEN_NAME);        // 与后台 Authorization 隔离
        config.setTokenPrefix("Bearer");
        config.setTimeout(2592000);             // 30 天
        config.setActiveTimeout(-1);            // 关键：会员不冻结
        config.setIsConcurrent(false);          // 单端登录
        config.setIsShare(false);
        config.setIsReadCookie(false);          // 只从 header 读
        config.setTokenStyle("simple-uuid");
        config.setAutoRenew(true);

        logic.setConfig(config);
        return logic;
    }
}
```

> 注意：项目现有 `TokenConfig` 会把**全局** `activeTimeout` 覆盖成等保值。上面给会员单独 `setConfig` 后，会员不受影响；后台仍按等保走。  
> 该 Bean 不会与 `TokenConfig` 冲突，因为 `TokenConfig` 改的是 `SaTokenConfig`（全局 Config 对象），会员用的是独立实例。

### 3.2 调用方式

推荐直接注入，避免静态类时序坑：

```java
@Resource(name = "stpMemberLogic")
private StpLogic stpMemberLogic;

stpMemberLogic.login(memberId, LoginDeviceEnum.WEIXIN_MP.getDesc());
String token = stpMemberLogic.getTokenValue();
Object loginId = stpMemberLogic.getLoginIdByToken(token);
stpMemberLogic.logout();
```

若想写起来像 `StpUtil`，再加一个门面类 `StpMemberUtil`（内部持有同一个 Bean，用 `@Component` + `@Resource` setter 注入静态字段），但**不要** `new StpLogic` 后再 `setConfig`，否则会变成两个实例。

### 3.3 拦截器隔离

```java
// MvcConfig
registry.addInterceptor(adminInterceptor)
        .excludePathPatterns(SwaggerConfig.SWAGGER_WHITELIST)
        .excludePathPatterns("/api/**")     // 会员接口不再进后台拦截器
        .addPathPatterns("/**");

registry.addInterceptor(memberInterceptor)
        .excludePathPatterns(SwaggerConfig.SWAGGER_WHITELIST)
        .addPathPatterns("/api/**");
```

`MemberInterceptor` 与 `AdminInterceptor` 同构，但：

- 用 `stpMemberLogic.getTokenValue()` 读 `Member-Token` 头；
- 不做 `@SaCheckPermission`（C 端无 RBAC）；
- 会员 `disabledFlag` 为真时按未登录处理；
- 支持 `@NoNeedLogin` 放行（`/api/auth/wxLogin`、`/api/pay/notify`）。

### 3.4 顺带修复的隐患

`LoginService.getEmployeeIdByLoginId()` 仍是 `substring(2)` 不校验前缀。独立体系后它读不到会员 token，风险已消除；但**建议仍加 `1:`/`S:` 前缀白名单**作为纵深防御——成本 3 行，避免以后有人把 member token 塞进 `Authorization` 造成误判。

`UrlConfig.authUrl` 需过滤 `/api/**`，否则小程序接口会被收集进后台「菜单权限」的 URL 清单，污染配置界面。

## 6. 微信支付（JSAPI）接入设计

### 6.1 依赖

```xml
<dependency>
    <groupId>com.github.wechatpay-apiv3</groupId>
    <artifactId>wechatpay-java</artifactId>
    <version>0.2.17</version> 
</dependency>
```

### 6.2 下单流程

1. 业务校验商品/金额 → 生成 `order_no`（雪花或日期+随机），落 `t_wx_order`（`status=0 待支付`，`total_fee` 单位分）。
2. 调 `POST /v3/pay/transactions/jsapi`，关键参数：`appid`、`mchid`、`out_trade_no`、`notify_url`、`amount.total`、`payer.openid`（登录时已存，**不要前端传**）。
3. 拿到 `prepay_id`，服务端用**商户私钥**对 `appId\ntimeStamp\nnonceStr\nprepay_id=xxx\n` 做 SHA256withRSA 签名，返回前端：

```json
{ "appId": "wx...", "timeStamp": "1710000000", "nonceStr": "xxx",
  "package": "prepay_id=wx...", "signType": "RSA", "paySign": "xxx" }
```

1. 小程序 `wx.requestPayment(...)`。

### 6.3 回调处理（最容易出事的地方）

```
POST /api/pay/notify  @NoNeedLogin
  1. 读取原始 body（@RequestBody String，不要先反序列化）
  2. 用微信平台证书/公钥验签 Wechatpay-Signature / -Timestamp / -Nonce / -Serial
  3. AES-256-GCM 解密 resource（密钥 = APIv3 Key）
  4. 落 t_wx_pay_notify_log（含 notify_id，唯一索引防重）
  5. 事务内更新订单：只允许 0 -> 1，受影响行数为 0 直接返回成功（幂等）
  6. 发订阅消息（失败不影响支付结果，异步重试）
  7. 返回 {"code":"SUCCESS","message":"成功"}
```

必须注意：

- **验签与解密不可省**，微信回调是公网入口，任何人可 POST。
- 响应体必须是 `{"code":"SUCCESS"}`，否则微信会重推（重推 8 次左右）。
- 订单状态更新用「条件更新」`update ... where order_no=? and status=0`，靠 DB 保证幂等，不要先查后改。
- 金额以微信回调的 `amount.total` 为准，与本地比对，不一致则告警不发货。
- 回调接口要排除登录校验，且在 member 拦截器里放行。

### 6.4 兜底

- 主动查单 `GET /v3/pay/transactions/out-trade-no/{no}?mchid=`，用 SmartJob 每 5 分钟扫 `status=0 且创建时间 > 5 分钟` 的订单补偿。
- 关单 `POST /v3/pay/transactions/out-trade-no/{no}/close`，超过 2 小时未支付自动关闭（定时任务）。
- 对账（可选 P4）：下载交易账单 + 本地比对。

### 6.5 证书与密钥

| 项                        | 存放                                     |
| ------------------------ | -------------------------------------- |
| 商户私钥 `apiclient_key.pem` | 服务器文件路径，**不进 git**，权限 600              |
| 商户证书序列号                  | 配置项                                    |
| APIv3 密钥                 | 环境变量                                   |
| 平台证书                     | SDK 自动下载更新（`RSAAutoCertificateConfig`） |

## 7. 订阅消息接入设计

### 7.1 流程

1. 前端在**用户点击的时机**调 `wx.requestSubscribeMessage({ tmplIds: [...] })`（不能自动弹）。
2. 把授权结果上报 `POST /api/subscribe/record`，落 `t_wx_subscribe`（一次性订阅记可用次数）。
3. 业务触发时后端调：  
   `POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=xxx`  
   body：`touser`(openid)、`template_id`、`page`、`data`、`miniprogram_state`、`lang`。
4. 成功后扣减一次；失败按错误码处理。

### 7.2 错误码处理

| code  | 含义              | 处理              |
| ----- | --------------- | --------------- |
| 43101 | 用户拒绝或订阅次数用尽     | 标记失效，营销侧下次再引导授权 |
| 40003 | openid 无效       | 标记会员数据异常        |
| 42001 | access_token 过期 | 刷新后重试一次（仅一次）    |
| 47003 | 模板参数不合法         | 记录日志，属于开发问题     |

> 一次性订阅「授权一次只能发一条」，所以**每次业务动作前都要重新引导授权**，不能靠缓存一直发。

## 8. access_token 与并发

订阅消息、手机号等接口都要 `access_token`，微信侧**全局唯一**，并发刷新会互相顶掉。

```java
public String getAccessToken() {
    String cached = redisService.get(WxRedisKeyConst.ACCESS_TOKEN);
    if (StrUtil.isNotBlank(cached)) return cached;

    RLock lock = redissonClient.getLock(WxRedisKeyConst.ACCESS_TOKEN_LOCK);
    try {
        if (lock.tryLock(3, 10, TimeUnit.SECONDS)) {          // 多实例防击穿
            cached = redisService.get(WxRedisKeyConst.ACCESS_TOKEN);
            if (StrUtil.isNotBlank(cached)) return cached;
            WxAccessTokenVO vo = doGet();
            redisService.set(WxRedisKeyConst.ACCESS_TOKEN, vo.getAccessToken(), vo.getExpiresIn() - 300);
            return vo.getAccessToken();
        }
        throw new BusinessException("获取微信凭证繁忙，请重试");
    } finally {
        if (lock.isHeldByCurrentThread()) lock.unlock();
    }
}
```


````

- 提前 300s 过期，避免边界失效。
- 支付走证书体系，与 access_token 无关，两者独立。
````

## 10. 安全清单

| 项             | 要求                                              |
| ------------- | ----------------------------------------------- |
| `session_key` | 只在服务端短期保存，禁下发、禁落库、禁日志                           |
| `code`        | 一次性、5 分钟有效；前端不得传 openid / 手机号                   |
| 手机号           | 只信 `getPhoneNumber` 返回值；不上报前端手机号                |
| 回调            | 验签 + 解密 + 幂等，缺一不可                               |
| 金额            | 服务端计算，`amount.total` 与本地比对                      |
| 越权            | 订单查询校验 `member_id` 归属，防改 `orderNo` 查他人订单        |
| 防刷            | `wxLogin` 按 IP + openid 限流（Redis 计数，60s/10 次）   |
| 日志            | openid、手机号脱敏                                    |
| 并发登录          | `isConcurrent=false`，换设备踢旧 token（C 端可接受）        |
| token 有效期     | 30 天 + auto-renew；前端收到 30007 重新 `wx.login` 静默续期 |
