# 2026-10-20

## 《让我做》微信小程序 · v1 方案与前端骨架

**定位**：熟人关系（家人/室友/好友）的任务委托与提醒。核心差异是与"关系"绑定、双方视角对称、文案去企业化。

**产出**
- `docs/让我做-v1-产品与技术方案.md`：产品定位、角色与关系模型、状态机、11 个页面路由、数据结构（TS 接口 + MySQL 表映射）、接口契约与错误码、订阅消息触发点、UI 设计系统、交互细节、验收标准。
- `prototype/index.html`：7 屏高保真原型（任务中心双角色、布置、详情、完成、好友、我的）+ 设计令牌 + 状态/空态/骨架屏面板。375×780，纯 CSS，无依赖。
- `miniprogram/`：接口层骨架（config / utils/request / constants / services / mock）。已用 Node 跑通全链路自检。

**关键设计决策**
- 逾期不是独立状态，而是 `status + deadline` 派生的 `displayStatus`；查询时 `status=overdue` 由服务端翻译成 `status IN (pending,in_progress) AND deadline<NOW()`。
- 角色是任务维度的（creator/assignee），不是账号维度；同一条任务在两侧显示不同文案与按钮。
- 权限位（canAccept/canComplete/canEdit…）由服务端计算，前端只读，避免两端规则漂移。
- 订阅消息在「发布/接受/完成/打开设置」四个高意愿节点攒额度，拒绝授权不阻断主流程。
- 请求层强制：页面零 `wx.request`、零 URL 字面量；切换后端只改 `config/index.js` 的 ENV。

**技术栈**：原生小程序 + WXML/WXSS，后端预留 SpringBoot + MySQL + Redis（本阶段 Mock）。id 一律 string（防 Long 精度丢失），时间一律 ISO8601 字符串。

**下一步（M1）**：按文档第 4 章路由表生成 `app.json` 与 11 个页面骨架，实现 components/（task-card、status-tag、role-switch、filter-chips、empty-state、skeleton 等）。

**注意**：原型中 `.tag{margin-left:auto}` 在纵向 flex 容器里会把标签推到右侧，详情页 hero 与状态面板都踩过，已用局部覆盖修正；迁移到 WXSS 时建议把 `margin-left:auto` 只写在 `.task-top .tag` 上。

## 同日追加：v1.1 三项升级（液态玻璃 / 多人任务 / 服务通知同构）

**1. 液态玻璃 banner**
- 结构：`.glass-banner` 内 4 团 `filter:blur()` 色斑（#FF5F35 橘 / #1FC49B 薄荷 / #FFAE7E 杏 / #FFD0C0 粉）+ `.glass` 覆盖层。
- 玻璃：`backdrop-filter: blur(32rpx) saturate(190%)`；白渐变 `.62→.20→.42`；3rpx 白边；`inset 0 4rpx 0 #fff` 顶部高光；`::before` 双层 radial 做镜面反射 + 二次折光。
- 纪律：玻璃里只放结论不放列表；色斑必须饱和否则玻璃发脏；`@supports not (backdrop-filter)` 降级为不透明渐变；整页只许一处 blur。

**2. 多参与者**
- `t_task.assignee_id` 废弃 → `t_task_participant`（task_id+user_id 唯一）。task 上只留 `completion_mode`。
- 两层状态：参与者 `pending|accepted|done|rejected|skipped`，任务聚合状态由 `aggregate(task)` 算出并**写入时落库**。逾期仍是派生。
- `aggregate` 顺序：定时未开始且无人动作→scheduled；全拒/全跳→rejected；全员done 或 any模式有人done→completed；有人accepted/done→in_progress；否则 pending。
- 任一人完成 → 其余 pending/accepted 置 `skipped`，不再提醒。
- 委托人可把自己加进参与者（家庭场景"一起干"），详情页同时给"撤回/加人"和"完成我这份"。
- 加人限制：仅 pending/scheduled 且 <10 人；已完成任务不可加人（避免冒出新的待办）。

**3. 服务通知**
- 微信卡片样式不可改，只能控制「模板标题 + 关键词标签 + 值」，所以模板设计=界面设计。
- 4 个模板：TASK_ASSIGNED / TASK_REMIND / TASK_COMPLETED / TASK_ALL_DONE，统一 3~4 个键值行，第一行永远是任务名称。
- 新增小程序内 `pages/messages/index`（消息中心）作为第二通知面，卡片复刻微信样式；`t_notice` 存 `fields(json)` 直接驱动渲染。
- Mock 侧通知必须按 `toUserId` 投递并过滤，否则会把自己的操作推给自己（已修）。

**验证**：`lmd-check2.js` 全绿——多人聚合、any/all 两种模式、skipped 分支、重复完成 40900、非参与者 40300、空参与者 42200、加人限制、通知未读数与已读、存储状态与聚合结果全量一致。

**文件**：`docs/让我做-v1.1-产品与技术方案.md`（原 v1 文档已重命名）、`prototype/index.html`（8 屏）。

## 同日：可运行的小程序 v1.1 落地（13 页 + Mock 全链路）

**工程**：根目录 `project.config.json`（`miniprogramRoot: miniprogram/`，appid 暂用 `touristappid`），代码在 `miniprogram/`，文档/原型/tools 通过 `packOptions.ignore` 排除。共 145 个文件、401KB。

**已完成页面（13）**：launch、tasks/{index,create,detail,complete,participants}、messages/index、friends/{index,detail,invite}、mine/{index,profile,settings}。tabBar 3 项，`tasks/index` 用自定义导航（sticky，需 statusBarHeight + 胶囊高度）。

**关键实现决策**
- **零自定义组件**：v1 用 `app.wxss` 全局类 + WXML 复用，先跑通链路；抽组件留到 M2（文档已同步说明）。
- **图标脚本生成**：`tools/gen-assets.js` 用「线段/圆/圆角矩形 SDF + 4×4 超采样 + 手写 PNG 编码（zlib+CRC32）」生成 76 个单色图标（tabBar 81×81，内联 48×48，7 种颜色）。原因：tabBar 只认图片，WXML 没有 SVG sprite。
- **液态玻璃改用径向渐变**：`filter: blur()` 在部分安卓 WebView 不生效会让色斑变硬边圆；改成 4 团 `radial-gradient` 铺底，任何机型都成立，`backdrop-filter` 只做增强。色源半径 400/380/520/320rpx，衰减 60~68%。
- **`avatar` 的 `overflow:hidden` 会裁掉状态点**（`::after` 定位在 -2rpx），已移除，改由 `.av-img` 自己 inherit 圆角。
- **首页摘要**新增 `GET /tasks/summary`（等我的 / 我派出的 / 逾期 / 在等我的人），避免前端用分页数据凑数。
- **好友关系 id ≠ 用户 id**：`friend.list` 返回的 `id` 是关系 id，`userId` 才是人。选人页曾误用 `f.id` 导致创建任务报「有参与者还不是你的好友」，已统一用 `userId`。
- 页面铁律仍成立：零 `wx.request`、零 URL 字面量、零 `res.code` 判断。

**验证手段（无开发者工具）**
- `tools/check.js`：页面四件套、JS 语法（vm 编译）、require 路径、图片引用、tabBar、跳转目标、事件绑定是否存在、WXML 标签平衡。
- `tools/sim.js`：桩出 `wx/App/Page/getApp`，真实加载 app.js 与 13 个页面，跑登录→列表→切角色→筛选→接受→详情→完成页→选人→创建→通知→好友→我的。**测试时把 mock 延迟置 0**（否则 280~620ms 随机延迟会导致断言提前失败）。
- 两个脚本均全绿。sim 跑出的两个真实 bug：登录页不点按钮不会自动登录（测试写错，非代码问题）、选人页关系 id 混用（真 bug，已修）。

**坑点记录**
- 静态检查器解析 WXML 时，属性里的 `>=`（如 `wx:if="{{a >= 0}}"`）会被当成标签结束符；需先把 `{{...}}` 整体替换成占位符再判平衡。
- 跨行自闭合标签（属性折行、`/>` 单独一行）要用 `/\/\s*>$/.test(m[0])` 判断，不能依赖分组捕获。

**待用户补**：4 个订阅消息模板 id（`config/notify.js`）、真实 AppID、后端（`aggregate()` 需后端写等价实现）。

## 同日：底部 tabBar 改为悬浮液态玻璃

**为什么必须改架构**：原生 tabBar 由微信渲染，CSS 碰不到。悬浮/玻璃效果只能 `"tabBar": {"custom": true}` + 自建 `custom-tab-bar/` 组件。

**实现**
- `custom-tab-bar/index.{js,json,wxml,wxss}`：胶囊 112rpx 高、圆角 56rpx、左右各留 40rpx、距底 `24rpx + safe-area`。
- 玻璃配方沿用 banner：白渐变 `.86→.60→.74` + `backdrop-filter: blur(40rpx) saturate(180%)` + 顶部内高光 + 带品牌色落影；额外加两团极淡折射色（橘 .18 / 薄荷 .15）和顶部白色折光，避免胶囊死白。
- 选中态：`rgba(255,107,74,.13)` 胶囊底 + 品牌色图标文字 + 图标微缩放。

**三条必须记住的约束**
1. 组件实例按页面独立 → 每个 tab 页 `onShow` 都要 `this.getTabBar().setData({selected:n})`，否则切回来高亮错。
2. 悬浮层不占布局 → tab 页末尾加 `tab-space`（200rpx + safe），列表页 `padding-bottom: 300rpx`，FAB 从 140rpx 上移到 172rpx。
3. 点击时先 `setData({selected})` 再 `switchTab`，别等目标页 onShow，否则有"点了没反应"的观感。

**降级**：不支持 backdrop-filter 时白渐变仍可读，不需要额外兜底；但**不要**再叠 `filter: blur()`，会掉帧。

**文档同步**：方案新增 8.4.1「悬浮液态玻璃 tabBar」；并把"整页只允许一处 backdrop-filter"修正为"最多两处（banner + tabBar）"，因为现在确实有两处。

**验证**：`tools/check.js` 增加 custom:true 时的四件套检查；静态检查 + 运行时 sim 均全绿（149 文件）。

## 同日：Logo 与品牌板

**做法**：矢量绘制（SVG），不是 AI 位图。原因是小程序图标会被压到 40px 甚至 28px，生成图在这个尺寸糊；矢量可无损导出任意尺寸。

**图形**：圆角对话气泡 + 品牌色对勾 + 左下尾巴。含义：气泡=一句口头交代，对勾=做完了。外轮廓刻意用气泡而不是勾选框，因为这个产品起点是微信里那句「帮我把衣服晾一下」。

**参数**：气泡 560×470、圆角 152，位于 232,232；对勾 stroke 88、round cap，从 (402,468)→(484,552)→(634,390)；底色渐变 #FF8A5F→#FF6B4A→#EE4E28，叠一层左上白色径向光。

**踩过的坑**：尾巴第一版用「三角形从气泡下方另起」，顶部与气泡底边之间留了个缺口，看起来像贴了张纸。正确做法是让三角形的两个顶点落在气泡边界上（306,656 / 432,700），再向下收尖到 (300,806)，并给三角形加同色 stroke-width 28 + round linejoin 把尖角磨圆。

**产出**：`assets/logo/` 下 icon.svg + 1024/512/240/144 PNG + brand-board.png + preview.html（品牌板源文件，浏览器直接开）+ render.html（按 ?f=&s= 渲染任意尺寸）。`miniprogram/images/logo.png` 用于启动页和服务通知卡片头像（`.wx-logo` 由文字改成图片）。

**注意**：品牌色底（#EE4E28）上图标几乎融掉，只能靠投影分离——品牌板里改成了「浅色底」演示，更贴近真实场景（App 内是浅色底）。
